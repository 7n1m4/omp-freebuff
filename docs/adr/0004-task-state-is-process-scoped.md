# ADR-0004: Task state is process-scoped, and session teardown is refcounted

OMP binds the extension factory per session — a subagent gets its own `ExtensionAPI`, tool registry and `session_shutdown` — while the module graph evaluates once per process; `ctx.setInterval` dies with that binding's dispose, `session_shutdown` fires only from a real dispose, and `ctx.reload()` re-evaluates the graph without any shutdown. So one **process-scoped singleton** owns the Queue, the Lock, the Instance and the Task registry; the **Watchdog runs on a process-scoped timer** the extension owns (plain unref'd timers, contained throws — never `ctx.setInterval`); `session_shutdown` handlers are **refcounted**, the teardown (kill Instance, `abandoned@<ts>`, delete Lock) running when the **last** session ends; and **ownership is a pair** — a Lock naming our own pid with no live in-memory Task behind it is stale, the reload path, reclaimed lazily like any other. Corrects the watchdog placement fixed by [pi-freebuff#7](https://github.com/vadash/pi-freebuff/issues/7); resolved by [pi-freebuff#8](https://github.com/vadash/pi-freebuff/issues/8). A session-scoped registry contradicts ADR-0001; teardown on any binding's dispose lets a parked subagent kill a Task it does not own. Consequences: nothing that outlives a turn hangs off `ctx`; `session_start` may arrive repeatedly and means nothing about freshness; a mid-Task reload is indistinguishable from a crash — the Task is abandoned and the Instance reclaimed at the next claim.
