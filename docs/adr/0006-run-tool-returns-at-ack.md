# ADR-0006: The run tool returns at the Ack, and the answer rides the aside push

A blocking run made the parent's session unusable for up to twenty minutes and made a hang indistinguishable from a slow model, and the tool-call channel cannot carry a later answer (`onUpdate` dies with the call). So `freebuff_run` returns at the Ack — `{taskId, phase: "working"}`, or `{taskId, phase: "queued", position}` — a submit receipt, never the answer; the answer is delivered twice by design: the **settle push** (`deliverAs: "aside"`, never steer) and the idempotent **`freebuff_progress` poll**, both verbatim and untruncated. ADR-0008 later added a third, equivalent channel: the bounded blocking **`freebuff_wait`**, returning the same verbatim answer at the Task's Verdict and a progress snapshot at its bound. One Task at a time, queue depth 4; only the **Owner session's** calls are answered, any other session refused with a message naming the owner — extension tools are additive in task subagents, so an unrefused call would push an answer onto a binding that is gone. The surface hangs off the process-scoped singleton (ADR-0004), so it survives session switches, subagent dispose and in-place reload. Resolved by [pi-freebuff#20](https://github.com/vadash/pi-freebuff/issues/20). Steering the answer into the conversation violates the map's locked no-steer constraint; a handle-plus-`onUpdate` shape reaches nothing after the call returns.
